# 保留设计意图的版本迁移

> 何时读：游戏版本更新后迁移本 MOD，或做三方比较。不必读：同版本内的普通修复。

## 三份数据，而不是新旧文件覆盖

- A：上次已核验的原版基线（WORK/baselines/<version>）。
- M：当前 MOD（修改前完整备份 + SHA-256 manifest）。
- B：本机更新后的原版。

对可解析对象做三方比较：M=A 的部分接受 B；B=A 的部分保留 M；双方都改变则按“设计意图约束”解决。没有 A 时不得把 M 与 B 的差异自动归为过时内容，应先识别用户设计并保守保留；报告无法推断的差异。

## 复查 MOD 覆盖的原版文件和键

先保留旧版原文、哈希与源码索引，再用 `catalog.py status`、`refresh`、`snapshot` 记录新版。用 `vanilla_overrides.py` 枚举主 MOD 与 game、DLC 及引擎层的同路径文件，包括内容相同的副本与二进制资源。逐文件用旧、新原版哈希筛出新增、删除、改动；缺旧原文时注明证据来源。

另按引擎读取的对象类型对照两版原版与 MOD 的定义键。去掉 `REPLACE:`、`INJECT:` 等操作前缀，再查异文件同名定义以及注入的具体子项。事件核对命名空间和完整 ID，本地化按语言递归查键，defines 查组和字段。on_action 加挂、历史追加和整个对象替换分别判断；只合入被 MOD 挡住且与设计相容的改动。

## 地图的持久身份是 province 集合

基线记录每个 province 的 region、owner；另保存 MOD 的设计归属与自定义地区。更新后省界改变时，逐 province 对照 old region→new region→MOD owner，不按文件名或原版新 owner 决定目标。

例如本 MOD 要完整 USM 广东：原版把 xXXXXX 移往英国某地区，并不授权把它改给 GBR。保留 USM owner；按坐标/连通性和设计选择保留广东或归 USM 台湾。若颜色 ID 消失/拆分，不凭 ID猜测，使用旧新 province 图的像素重叠/地理位置映射并列出不确定项；缺旧图则停在可审阅的冲突，不能自动发明地块。

检查：所有有效陆地 province 恰好属于一个地区、且恰好有一份历史归属；owned_provinces 属于该地区；hub合法；每个 `region_state:TAG` 存在对应 state；人口/建筑/资源总量按意图守恒；无幽灵 owner；新地区属于正确战略区域。

## 机制变化

对 laws/IG/social classes/军事等，先写“旧代码试图实现什么”，再查新引擎同义机制。旧字段被废弃时不能只删到无错误。新引擎吸引逻辑/立法支持模型变更，需要改对应层并在游戏里观察相同预期行为。标记新增原版默认值，不覆盖自定义平衡。

## 每次迁移产物

1. 原 MOD 独立备份目录和哈希清单（含隐藏 `.metadata`、gfx、本地化）。
2. 原版版本/build/相关源哈希及文本基线，不写回本体。
3. 变更报告：变更文件、意图、旧新行为、验证证据、未决冲突。
4. 新版本执行日志与保存的新开局测试存档；现有存档兼容性单列，不能由新开局推断。
5. 更新技能索引与受影响配方；同版热修也比较哈希。

备份、候选MOD、测试MOD均放主 MOD 目录外，避免游戏误载测试脚本。不要使用递归同步删除更新本体/工坊/资料。导出应先写候选目录，再完整校验，最后以可回滚文件集应用。

## 1.15 保留旧文化的引用检查

除文化、人口与名称外，核验每种文化的生活水平、文化接纳与狂热度。逐一从静态修正追到 modifier_type_definitions 的实际定义，并对照同版同类文化。人口与文化 ID 检查通过仍可能遗漏这一级。旧版 Tiger 对新版字段可能误报。先与本机同版本原例核对，再复跑相同配置比较改动。
