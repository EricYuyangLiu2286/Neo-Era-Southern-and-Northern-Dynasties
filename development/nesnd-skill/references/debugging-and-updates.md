# 修复问题与游戏更新

> 何时读：修作者报告的问题、读 error.log 或存档；游戏更新后的第一步。不必读：设计新内容。

## 1. 修一个问题

作者刚在游戏里看到问题时，日志还在：先把 `logs/` 整组复制到工作台 `reports/<日期>-<主题>/logs/`，下次启动游戏会轮转覆盖它们。

1. **拿到证据**：作者的描述、截图、`logs/error.log`（注意轮转，见 verification.md）或存档。记下出错时的游戏版本和 MOD 提交。若已崩溃，同时保存时段相符的 `crashes/<本次运行>/`；从其中 `logs/error.log` 的加载阶段找第一条相关错误，再与操作时段及 `exception.txt` 对时。人物头像的 `Invalid promote`、`wrong constness` 和 `No context supplied` 见[人物提示的上下文](compatibility.md#日志人物像与悬停)。
2. **定位**：在日志里找最早指向本 MOD 的文件和行；用 `scripts/catalog.py find <名称>` 或 Toolkit 的跳转找到定义。沿调用链读一遍：入口 → 条件 → 效果 → 本地化。
3. **对照**：
   - 原版同类写法是否不同；
   - 作者原作（tag `original-20261030`）里这条链原本是否正常。原来能触发、现在不触发的，对照最初版本的 trigger、on_action 和 outcome，找出后来改动了什么。
4. **改根因，改最小**：只改造成问题的地方。同一错误写法在其他文件也有时，一并修正并列出；其他无关问题只列出，不顺手改。
5. **检查**：跑解析和 Toolkit；确认原来的错误会被检查发现、修改后不再出现。交付说明写清是否需要作者在游戏中复测。

### 新开局是验收基准

- 修复按修正后版本的新开局判断是否成功。旧存档只用来定位问题从哪个阶段开始。
- 旧存档里由错误脚本造成的阵营、胜负、人口或归属，不是正确结果，也不需要纠正。
- 不写救档、补发奖励、复活国家或只为旧档存在的分支，除非作者专门要求。
- 读存档时先复制到工作台，用工作台 `tools/` 里的 Rakaly 解码；不改原存档。

## 2. 游戏更新了

1. **确认版本**：`INSTALL/launcher/launcher-settings.json` 或日志中的版本号，与 STATUS.md 的基线比较。
2. **刷新索引**：`scripts/catalog.py status`，有变化就 `refresh`，读它生成的差异报告。请作者在游戏内重新导出 script_docs（更新用户文档目录 `docs/*.log`）。
3. **先找出失效引用**：跑 Toolkit / Tiger 和 `scripts/audit.py`，按文件归组。Tiger 规则可能落后于新版本，报错先对照新原版。
4. **迁移**：按 [migration.md](migration.md) 做三方比较，保留本 MOD 的领土、人口、文化与制度意图；被删除的旧接口改写为新接口，不只删到不报错。
5. **收尾**：更新 STATUS.md 的基线；技能和参考文件中写死旧版本号的条目，逐条核对后改写或删除。迁移后的第一次实机测试由作者决定何时进行。

任务提示词的修复样例（HNA 在明内战开始时独立）见主 MOD `docs/agents/prompt-kit.md` §3：先说观察、怎么观察到、期望，再列要排查的调用顺序。
