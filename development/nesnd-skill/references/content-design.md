# 内容设计：形状、尺寸与层级

> 何时读：设计新内容，或改造日志链、事件、按钮、进度条之前。不必读：只改玩家文字、只调数值（读 numeric-scale-contract.md）、只修一个引用报错（读 script-safety.md）。

维多利亚3是互相咬合的系统。一项内容不是“一个日志加几个按钮”，而是一棵树：

```
根日志（玩家面对的处境与总目标）
├─ 状态量：原生条件 / 计数 / 进度条（谁写入、周期、上下限）
├─ 玩家行动：按钮或决议（每个都有可见反馈，多数触发事件）
├─ 世界反应：脉冲随机事件、危机事件
├─ 分支：选择后开启的子日志（各有自己的小状态量和行动）
└─ 结局：成功 / 失败 / 超时 / 失效（各有一个事件或明确效果）
```

写代码前先画出这棵树，标出每个节点的主人（国家/全局）、玩家在哪里看到它、它怎样结束。

## 1. 先选形状

下面四种来自原版 1.15，第五种是作者自己的法兰西链。新内容先归入其中一种，再按对应规模写。

### A. 里程碑链

原版 `00_liberalism.txt`。每个日志一个具体目标（法律 + 建筑等级与雇佣率 + 合法性≥50），完成时触发一个事件，并设变量开启下一环。没有按钮，没有进度条，每个日志约 40–100 行。
适用：制度建设、发展目标、“达成即奖励”的内容。

### B. 计时压力

原版 `00_opium_wars.txt`：每月脉冲在满足条件时给计数变量 +1，用原生 `progressbar`（按月显示）。另有两个按钮（禁/解禁），成功、失败、超时三个结局，`timeout = 3650`。月度随机事件权重 `200 = 0` 对 20，约每月 9%。
原版 `01_coup.txt`：用 scripted 进度条，达到 120 胜、降到 0 败，`timeout = 730`。每周一个检查事件，每月从 10 个随机事件中抽取（约 40%）。参与者消失时由一个 hidden invalid 结局收尾（`NOT = { exists = scope:golpista_ig }`）。
适用：危机、限时博弈、需要玩家持续回应的压力。

### C. 主日志 + 子目标

原版 `00_meiji_restoration.txt`：主日志有 12 年时限和几个关键按钮，经济、军队、外交子日志各管一项，每年各有自己的随机事件。超时按已完成的进度给部分结果。
原版 `08_tsarpoints.txt`：主日志统一管理资源，子目标完成任意 3/4（`calc_true_if = { amount >= 3 … }`）；失败时若进度大于 0 仍给部分奖励。
适用：一个国家的长期改造，由几条可并行的路线组成。

### D. 原版的对立势力条

原版 `01_french_monarchism.txt`：一个日志挂三条势力进度条和三个按钮，每周、每月脉冲比较哪一方领先，触发巩固或政变事件。
适用：几方势力争夺同一结果。

### E. 作者的深系统（法兰西帝国链）

原作见 tag `original-20261030` 的 `ce_french_empire*.txt` 和 `ce_fra_unrest_events.txt`：

```
维持拿破仑王朝（根，1836→1860/1870）
├─ 王朝稳定度 0–1000，起点 750，约 20 项具名月度来源（摄政、人物人气、运动、IG、GDP 排名、
│   工业利润、法律、生活水平、官僚、机构、厌战、破产、对立王朝在场），由隐藏周事件重算
├─ 月度随机风味事件 8 个（每个 2–4 选项，改变稳定度 ±25…100；300 = 0 对 130，约每月 30%）
├─ 4 个互斥路线按钮，1838.12 前必须选（否则失败）
│   ├─ 保卫王朝 → 压制共和派子日志（共和呼声 0–100；满条触发 5 选项危机事件）
│   ├─ 向共和进发 → 玩家扮演共和派（5 个行动按钮，同时只能进行一项）
│   ├─ 奥尔良 / 波旁 → 政变准备子日志（0–200），成功或错失各有事件
└─ 结局：成功、失败、失效各一个事件
合计：5 个日志、4 条进度条、13 个按钮、25 个事件
```

适用：一个国家的核心政治斗争，值得做成深系统时。

作者原作的 CNE 地权革命是 B 的变体：完成条与失败条年度竞速；几个旁支日志（市场接入、对西秦战争、对明战争等）达成时推进完成条，未达成时每年推进失败条，每年约 10% 抽一个随机事件。

## 2. 尺寸

按日志统计（`scripts/je_stats.py`，2026-11-06）：

| | 原版 1.15（293 个） | 作者原作 `ce_`（24 个） | 代理 `nesnd_`（132 个） |
|---|---|---|---|
| 每个日志行数中位数 | 103 | 144 | 27 |
| 有按钮的日志占比 | 24% | 29% | 51% |
| 单个日志最多按钮数 | 12 | 14 | 73 |
| 有进度条的占比 | 24% | 54% | 37% |
| 用 timeout 的占比 | 19% | 12% | 1% |
| 脉冲挂随机事件的占比 | 24% | 17% | 0% |

读法：
- 原版和作者的日志把条件、效果写在日志里，所以较长；代理的日志只有 27 行，逻辑分散在别处：`nesnd_` 文件共定义约 2,400 个 scripted trigger/effect/value，当前 `ce_` 文件约 44 个。读者和玩家都难以从日志看出它在做什么。
- 多数日志没有按钮。按钮用于真正的选择或行动，不用于“开始/停止”开关。代理的营产日志为每个州写一对开始/停止按钮（共 48 个），原版的做法是一个按钮加事件选项，或用 `ordered_scope_state` 自动选目标。
- 时限和随机事件是原版的主要节奏工具，代理几乎不用。长期日志应考虑 `timeout` 和超时结局；持续性的日志应在脉冲上挂风味事件。

## 3. 每个节点的最低要求

- **开启**：`possible` 或由按钮/事件 `add_journal_entry`；需要提前显示时用 `is_shown_when_inactive`。
- **状态量**：一个数值只有一个写入者（脉冲或进度条的 `monthly_progress`，二选一）。来源用具名条目显示在进度条明细里。
- **行动**：按钮的可用条件用原生 trigger 显示；效果里给玩家看得见的结果（原生效果、`custom_tooltip` 或触发事件）。一次只能进行一项行动时，用一个锁变量。
- **结局**：原版日志中位数 2 个结局，最多 4 个。成功和失败各接一个事件或明确效果；超时用唯一的 `flags = { timeout }` 结局；对象消失用一个 hidden invalid 结局。不为想象中的情形加结局。
- **清理**：结局效果里移除本链变量；多处要清理同一组变量时，提取一个 cleanup effect（原版 `je_opium_wars_cleanup`）。

## 4. 兜底：用一行，不用一个系统

| 情形 | 原版做法 |
|---|---|
| 保存的对象可能不存在 | `scope:target ?= { … }` |
| 关键人物或 IG 消失 | hidden invalid 结局：`NOT = { exists = scope:x }` |
| 革命继承、转让 | `can_revolution_inherit = no`、`transferable = no` |
| AI 需要捷径 | 一个按日期或 `is_ai = yes` 的结局，或 `set_strategy` |

反例（2026-11-06 法兰西链）：代理为“法国存活但没有已整合州”加了五个 hidden invalid 结局、一个新 trigger 文件、一个事件、一个 12 个月修正和新本地化；新事件还在 `immediate` 里重复检查自己的 `trigger`。作者和原版对这种情形最多写一行守卫。

## 5. 改造现有链

先列出入口→状态→脉冲→选项→结局，搜索所有引用该链的事件 ID、变量和本地化键。保留外部入口，或明确迁移；新旧状态机不能同时结算。旧档迁移只在作者要求时做。

### 事件链与分支的登记

先查 GAME `events` 中 `type = country_event` 和需要的 effect；本项目入口 `events/flavorUSM_ce.txt` 的 `flavorUSM.1`，由 `common/on_actions/ce_code_on_actions.txt` 的月脉冲调用。链上每个节点需登记：事件 ID、调用者、guard 变量、玩家选项、AI权重、下一事件/JE、退出清理。

真实项目形状：
```text
trigger_event = { id = flavorUSM.1 popup = yes }
set_global_variable = flavor_USM_crisis_ongoing_global
add_journal_entry = { type = ce_usm_conflicts_within }
```

不要给所有分支共享一个模糊布尔标志。国家变量记录各国进度，全局变量仅记录真正世界共享状态；`save_scope_as` 目标在延时期间可能死亡/被吞并，后续用可空 scope/exists 保护。月脉冲不能每月重复开同一事件。测试每个选项及灭国/换统治者/JE失效的边界。

## 6. 文件功效与替代入口

推导走到死路时，先查“哪类文件拥有这个行为”，不要只在已知事件上加条件。

| 要改变的行为 | 查证入口 | 注意 |
|---|---|---|
| 宣战、主战目标 | `common/diplomatic_plays/`，本项目 `ce_diplomatic_plays.txt`、`nesnd_japan.txt` | 博弈选了哪个 war_goal；退让和正式开战分别验证 |
| 战争执行后再分国 | GAME `common/war_goal_types/war_goal_types.md`、`00_annex_country.txt` | `on_enforced` 追加效果；`kind = custom` 无预设效果 |
| 兼容已有战目标的回调 | GAME `common/on_actions/00_code_on_actions.txt` 的 `on_wargoal_enforced` | root=Country，`scope:target` 为被执行国 |
| 亡国后重建政权 | `docs/effects.log` 的 `create_country`；`country_definitions/`、`scripted_effects/` | 由存活的控制者调用；不重复刷已存活的 TAG |
| 法律与社会阶序 | GAME `law_groups → laws → ideologies → social_hierarchies → social_classes → modifier_type_definitions → GUI` | `on_law_activated` 的 root 是 law；固定阶序须每个职业恰好命中一个 class |

优先用本项目前缀的新条目或窄条件的 on_action 扩展，不整文件覆盖全局原版文件。

## 7. 规划

单一系统直接画树后实施。跨多个系统（例如同时改人口、地图和日志链）时，先写一页计划：玩家体验、树、涉及文件、不做什么。写在 `.scratch/` 对应 issue 里，不写进技能。

外交援助、供货和预算相关的需求，先读[原生条约、供给和援助](../lookup/native-treaty-aid.md)。

每个 idea 输出短实现说明：可用的机制、证据路径、实际可交互结果、引擎不支持之处及最接近方案。优先组合已有 JE/变量/事件/按钮/UI，而不是承诺新增引擎层。新版本未知字段必须等安装后查证。不要将“AI想支持某法”实现成直接 `activate_law`，也不要将“完整广东”实现成跟随原版国界的机械迁移。

实例：地权革命的胜负节奏估算 `WORK/reports/2026-11-09-land-review/sim/land_reform_sim.py` 与同目录 `odds.md`。规则逐条注明脚本出处，外部经济写成显式假设，分情景跑多次。要估一条日志链的完成概率或时间时照此做；一次性的确定性对照见同目录 `race_table.py`。
