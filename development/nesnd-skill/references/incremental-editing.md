## 一次工作先明确四个对象

主 MOD、编辑候选、冻结运行副本、测试存档分别记录绝对路径和 SHA。exports/<候选> 本身通常就是 MOD 根；backups/<版本>/mod 与 exports/runtime-<stamp>/mod 才有 /mod 子目录，先看 metadata 不靠拼接路径猜测。读取 active-work 后只回读本次依赖的计划与证据，不逐轮重新读完数百份报告。

先形成一项可评审的变化：玩家行为、前置条件、效果和收尾；记录新/旧规则冲突。例如引入拥明/拥吴竞争后，旧契约到100直接settled是冲突入口，不能只在旁边增加新bar。查完整读写链：入口→初始化→周期/按钮→事件选项→终局→清理→展示。`WORK/tools/dependency_graph.py --help`、`impact_query.py --help` 提供只读定位；用 rg 回读实际调用上下文，不把索引当引擎求值。

先建独立候选和备份；并行补丁声明共同父版本。`WORK/tools/combine_candidate_patches.py <配置.json>` 按 parent/candidate/base 合并，冲突即停，不能用后生成的整文件覆盖另一分支。保留差分、源指纹与 engine_verified=false，未测不改成accepted。

## 批次循环：先代码闭包，后集中实测

先区分接受的失败结果与实现缺陷。2026-11-01用户明确接受包括日本在内的玩家失国/GAME OVER；不以自动保控、复活或续玩救援作为默认交付门槛。当前调试优先核既定事件的先后、条件、完成结果与可达性，并记录难度/玩家行动空间；设计已明确就推进查证，减少重复设计追问。旧审查中基于已撤回假设的FAIL应保留原记录、更新当前分类；未选用备选保留源指纹，不自动整合。当前具体链路和授权以[任务索引](<D:/Users/Eric Liu/Documents/Paradox Interactive/Victoria 3/mod/Neo-Era Southern and Northern Dynasties/.scratch/debug-release/map.md>)为准。

适用于本项目多文件维护与debug；2026-10-31用户明确要求减少重复屏幕观察。不是先无限增加内容再一次验收，也不是跳过引擎验证。

1. **固定本批范围并集中阅读。** 恢复主计划、最新用户修正和发布阻断；按文件功效查当前本体/项目实例，写依赖与预期结果。只debug时冻结新增剧情、拆州、经济调数；修复已有路线断链仍属debug。
2. **成批完成实现。** 对相同发布闭包先完成全部已识别代码修改，各补丁声明父版本，做三方集成。未知接口先通过源码/文档查证；不要每改一个文件便冷启游戏。若核心接口只能靠引擎确认，可安排一次最小可行性探针，回到本批实现后再验完整链。
3. **统一 Python/MCP 检查与修复。** 复用现有parser、源码指纹、全局引用/地图/人口/本地化/资源检查、Tiger、真实MCP查询；事件图比较作者基准与候选，区分替代入口、断线、控制台QA入口。输出每项PASS/FAIL/NOT_RUN、证据路径、SHA和未解析范围。局部修复后重跑受影响检查；全局廉价引用门禁每个集成候选执行，不能只验主动改动的州。
4. **冻结并集中进游戏。** 同一批候选只挂载冻结副本，按覆盖表运行首次菜单预览、生产选项、必要成功/失败/中断/存读档场景；地图历史用新局。可将已证的只读引擎probe批量加入QA并采集原生存档/日志，少做重复屏幕来回；真实选国、必要UI/图像、路径与运行结果仍须实机。
5. **差异回到第一步。** 记录离线预测与实机差异、剩余BUG及其影响闭包，先修代码/检查器，再冻结下一批。已通过且未受影响的证据绑定SHA后复用，不反复重跑全年。同类问题查上游共因，不因一次失败马上另开功能线。

批次报告先告诉用户“改了什么、通过什么、还缺什么、是否能交付”，再给详细证据入口。不要用几十个候选名替代结果，也不要把成批工作拖成没有阶段收口的无限研究。

## 按改变选择证据

|改变|先在本地排除的问题|需要重做的引擎检查|

|随机姓名池|有效culture、名/姓池、混合文化、loc键、模板不变|新生成人物；旧档已存名字不会自动改|
|条件/按钮/选项/人物|完整状态转换、初始化、缺值、一次性、死亡/亡国/过期守卫|生产effect与实际选项、日/月脉冲、存读档；同tick QA与自然路线分列|
|政治竞争与自动换国|互斥立场、和平/战争入口、参与国快照、接收国存活、玩家身份|原控USM/AI USM/非USM玩家/多人情形分别验证；未测试多人不宣称支持|
|人口/PM/土地/建筑|固定地域±25%、群体守恒、PM链、资源、岗位粗算|新局周/月/季与必要年度；AI和玩家样本区分|
|边界/hub/港口|AST、唯一省色、hub/locator/路网/海港/引用闭包|新局地图、实际行军/舰队进出、战争与重载；旧存档不能验新历史|

Python 静态检查与原生存档断言可批量执行，MCP索引与Tiger/CWTools可定位错误；它们不模拟就业、市场、AI和引擎scope。引擎内只读probe可随月脉冲自动记录真实条件，减少来回点屏幕；仍需真实进入国家，记录加载版本和起始状态。不得伪称已具备无界面启动/选国能力。scripted_tests 输出位置和跳过结果语义见 validation.md。

保存失败样本→本地检查应当检出同一错误→修复→同场景引擎复测→记录剩余差异。例：map_transport_preflight.py 实测检出旧F的三处缺海港；修复版静态通过之后，还须原生港口节点/连接及实际出入航行。例：首次JE按钮预览缺变量不是日后初始化即可免责，必须回归第一次悬停。

增量范围由依赖决定，不能只列本轮主动编辑的文件。当前海域ID迁移反例：只验新拆州会漏继承文件的naval_exit；旧ID有的消失，有的仍有效却指错海。每次地图导出做全局引用/海域类型扫描；源海域、province图或基础路网改变时做全局港口地理闭包，细则见map-economy-design.md的海域迁移段。把“全图cheap引用检查”和“受影响几何/引擎检查”分开，既不反复重测无关经济，也不让局部绿灯替代全图依赖验证。

生成脚本另查数据库顶层形状。通用PDX parser接受匿名`{ namespace = ... event_id = ... }`，不代表事件数据库能注册里面的事件；events文件的namespace和事件ID必须直接在文件顶层。序列化根节点时核对输出前后完整顶层key列表，不只以“能parse回来”放行。脚本文件位置先用rg --files和文件名过滤定位；不要凭模块简称猜不存在的路径。

冻结同一批相关改动后启动一次；进局建立未干预基线，再另存分支。默认经济局不混入互斥选项累计、跳时、占领夹具。长耗时自然模拟只对仍有不确定性的依赖开展，已通过且未受影响的检查保留指纹后复用。

## 阵营网络和全球展示

先读主MOD common/journal_entries/ce_french_empire.txt，追到对应scripted_progress_bars、scripted_buttons、事件和replace文本。该文件实际有四条政治路径，不按用户简称推断只有三条。借鉴“立场→政治/经济条件→进度→结局”结构，不复制法国历史和权重。

立场（拥明/拥吴/中立/自立）、政治支持、军务/财政/供给准备、真实军事力量分开建模。准备分不等于实际军力；合计须写权重、上限、更新周期、缺失/亡国处理和AI依据。国家数量不能代替实力；殖民地资源角色不能被GDP权重完全淹没。开战/和平结算只取一次快照，防止之后切换立场重复领奖；持久旗与临时风险须有明确生命周期。

global JE 的 context、immediate_all_involved、参与国列表与GUI数据上下文都查当前原版实现；global不自动意味着所有国家能看见，也不保证按钮在被选国家执行。显示立场、各项准备、真实军力、总分算法和上次更新，按钮操作国需明示。完成条件中的raw template/变量不可直接泄漏为玩家提示，使用真实概念及custom_tooltip。

外交条约有自己的对象生命周期：创建与on-action绑定可能不同步，必须实机核同一真实ID。未绑定不能当作没创建；保留异常标记并阻止再申，避免重复生成无人管理的付款。到期只清自己未被改订的协议；除条款/金额外，还核binding期限，用户同额延长也属于新承诺。保留国境外领土时的字面首都映射也是地图依赖；新增州须重生映射和地域白名单，迁都未成功就不得继续割地。
