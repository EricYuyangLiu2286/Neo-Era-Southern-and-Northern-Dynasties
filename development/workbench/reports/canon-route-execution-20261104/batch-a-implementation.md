## State and timing details for the test phase

Global `nesnd_hus_registration_serial` is monotonic. `record_epoch`, `record_owner`, `record_state`, and `wait` have distinct roles. State 1 = global native timer running; 2 = eligible to settle; 3 = successfully settled; 4 = permanently retired; 5 = legacy local-clock custody. A missing wait is only meaningful after record existence, matching epoch and state checks. New `years=1` follows actual native set_global_variable lifetime usage; the optional country event uses months=12 and an at-most-once next-day retry for same-date expiry order. Monthly maintenance is the fallback if that country event does not transfer to a revolution winner.

Journal invalidation no longer deletes wait. Direct law activation is corrected through the documented law-root/owner on_action. No invented general country-created, generic tag-change, or remaining-variable-days interface was introduced. Dead origin objects are not treated as alive; legacy clock existence is guarded independently. Source-object disappearance in a damaged legacy save is explicitly unsupported as an exact-deadline reconstruction and enters conflict.

No claim is made yet about engine ordering of law callbacks, automatic inheritance, custom class dynamic modifier recognition, GUI layout, AI natural choices, or native global expiry versus month/year event timing. The approved frozen test matrix is in plan §12. Tests should include begin/wait/completed paths, direct or imposed reform, reversed callback order, source expiry before/after victory, and secondary callbacks after settlement.
