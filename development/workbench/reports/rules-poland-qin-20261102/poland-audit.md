## 已确认的源码缺陷

这里“确认”指可由当前代码、数据库类型或明确玩家文本证明的矛盾。影响等级 P1 为关键流程或错误对象；P2 为局部分支/结算/可见说明。全部 `ENGINE_NOT_RUN`。

### F01 · P1：波森通牒保存了错误类型的领土目标

- 证据：`common/scripted_buttons/ce_poland_scripted_buttons.txt:631`–`:633` 在 `s:STATE_POSEN`（state_region）上保存 `target_diplo_play_state`，然后才进入 `random_scope_state`，该层没有重新保存。其余九个地区按钮是在具体 state 层保存（例如 `:323`）。事件 `events/ce_poland_events.txt:97`–`:107` 对保存对象调用 `set_state_owner`，`:134` 又把它作为 return_state 战争目标。
- 触发：KRA 取得波森宣称、积满复国影响力，点击“波森或战争”，接收国选择任一结果。
- 后果：和平让地调用到不受支持的 state_region；拒绝分支传入错误类型的战争目标。不能认为波森与其余九州同样可完成。
- 最小修法：把保存语句移入 `random_scope_state`、紧邻 `owner` 之前；回复时重新核对象存在、`owner = root` 与 KRA 的有效性。

### F02 · P1：KRA 已有一部分西加利西亚，导致“西加利西亚或战争”无法使用

- 证据：按钮 `:189`–`:193` 要求本国完全没有该地区的任何 state；同一按钮 `:216`–`:217` 却只要求 KRA 有宣称且没有整个地区。开局 `common/history/states/00_states.txt:8382`–`:8389` 明确是 AUS/KRA 分持西加利西亚。
- 触发：沿开局状态给西加利西亚加宣称、积满进度；只要保有克拉科夫那部分领土，第一项条件始终失败。
- 后果：不能通过该机制收复奥地利持有的剩余部分；这不是兵力不足或难度偏高。十个复制按钮具有同类条件，后续任何分州也会重现。
- 最小修法：删除“本国零份额”限制，以“存在符合资格、owner 非 KRA 的具体州”作为唯一目标集合；可用性与执行使用同一筛选。

### F03 · P1：结束先清阵营标记，迟答结算事件失去支持/反对身份

- 证据：`.10` 选项 `events/ce_poland_events.txt:503`、`:516` 和 `.11` 选项 `:788`、`:810` 在选择时读取国家的当前 pro/anti 标记。子 JE 在完成/失败/无效时删除它们：JE `:486`–`:528`、`:584`–`:613`、`:638`–`:640`。此外 `ce_code_on_actions.txt:53`–`:58` 在全局结束后每月删除两标记。主 JE `.10/.11` 的有效期为 `duration = 3` 月，并未保存结算阵营。
- 触发：胜负后先让子 JE 完成清理，或把通知保留到下一个月，再选择结算选项。
- 后果：支持国应有的忠诚派/失败惩罚、反对国应有的激进派/奖励与宣称分支被跳过；`.10` 的临时州列表还可能因为分支不再进入而未清空。KRA 自己改 POL 的分支另按 tag 判断，不会因此自动获得正确的第三国结算。
- 最小修法：将阵营结果在单一终局入口锁定并执行一次；子 JE 不提前销毁结算所需身份。通知仅展示已结算结果，或使用不可变的事件 scope 值，最后统一清理。不要靠玩家必须立刻点击规避。

### F04 · P1：煽动叛乱实际从全世界随机选州

- 证据：按钮 `:2898`–`:2902` 虽进入 KRA，却调用无 limit 的 `random_state`；`:2948`–`:2957` 虽先选支持国，随后仍用无 limit 的 `random_state`。引擎明确其集合为全球。
- 触发：反对国点击“煽动波兰叛乱”或“煽动支持者叛乱”。
- 后果：5%/2% 激进化可能落到无关国家甚至按钮使用者的州，通知与进度打击仍发给原定对象。文本 `localization/simp_chinese/replace/ce_poland_l_simp_chinese.yml:155`、`:157` 明确限定波兰/亲波兰国家国内。
- 最小修法：两处改为 `random_scope_state`，保持当前国家 scope；必要时用相同的可选州条件保护按钮。

### F05 · P1：支持国进攻 KRA 时，被改成反波兰的是 KRA 自己

- 证据：`common/on_actions/ce_code_on_actions.txt:250`–`:256` 判断 target=KRA、initiator 带 pro 标记；`:258`–`:261` 却在 `scope:target` 删除 pro、设置 anti。
- 触发：某支持国作为外交博弈发起方进攻 KRA。`.97` 的长期停战可能降低常规发生率，但这是已登记的战争回调分支，任何确实进入该分支的外交博弈均写错对象。
- 后果：攻击者仍算支持国，KRA 被计入反对者，可能获得“阻击波兰”子 JE 和不一致的月度差值。
- 最小修法：第二分支的修改对象改为 `scope:initiator`；同时检查第一分支的转阵营清理是否只影响该国。此项不需要改变既定支持/反对设定。

### F06 · P2：宣称数量的支持方惩罚分支永远为假

- 证据：JE `:240`–`:244` 将 `ce_polish_claim_state_count` 初始化为 0；十个声索按钮只加 1（如 `:154`–`:159`），无负向更新。`.98` `events/ce_poland_events.txt:1249`–`:1255` 将 inverse 设置为原计数乘 -1；支持方进度条 `common/scripted_progress_bars/ce_poland_progress_bars.txt:299` 要求 inverse >= 3 才扣 2。
- 触发：任意合法声索数量 N≥0，包括声索三州及以上。
- 后果：-N 永远不可能 >=3，“声索过多”对支持方的月度惩罚没有可达输入。
- 最小修法：若设计为三次声索起扣 2，直接检查原计数 >=3；或保留 inverse 并改为 <=-3。是否按“累计声索次数”还是“当前有效宣称”计数属于独立设计问题。

### F07 · P2：10–19 点进度受到打击会被多扣到 0

- 证据：`.4` 的 `events/ce_poland_events.txt:209`–`:232` 先在 >=10 时减 10，再以独立 `if` 检查新值 <10 并归零；复国条在 `:234`–`:257` 重复该结构。
- 触发：例如进度 15，接受该事件选项。
- 后果：源码顺序为 15→5→0，实际扣 15；20→10 则只扣 10，出现不合理边界。第二条还错误用 `has_journal_entry = je_ce_polish_war_preparation` 保护 `je_ce_polish_reconquest` 的读取。
- 最小修法：第二个 `if` 改成 `else`，分别保护实际读写的 JE；或者使用原生进度条最小值处理单次 -10，先核引擎 clamp 行为。

### F08 · P2：中途取得波兰领土的国家只得到标记，没有真正加入全局日志

- 证据：`ce_code_on_actions.txt:117`–`:182` 每月给指定国家或十地区所有者增加参加标记。主 JE `:28` 只提供激活时 `should_be_involved`；整个闭包没有 `add_involved_country`、`on_become_involved_after_activation` 或对新参与者补发 `.97`。原版文档 `journal_entries.md:20`、`:165` 区分这两个阶段。
- 触发：一个开局未参与的国家在全局 JE 已激活后得到指定地区的一部分。
- 后果：变量显示“参加”但未登记为 JE involved，也不会收到选择阵营的初始化事件或最终 `*_all_involved` 结算；月度计数仅认 pro/anti，不认参加标记，因此它未必进入任何一方。
- 最小修法：月度发现新资格时对主 JE 显式 `add_involved_country`，在新增参与回调中一次初始化 `.97`；离场规则需与设计一致，不自动清掉其未处理结果。

### F09 · P2：两种援助通知引用了从未在该调用链保存的国家

- 证据：筹款和外交声援按钮 `:2724`–`:2737`、`:2761`–`:2775` 分别触发 `.15/.14`，未保存 `ce_strong_power`。这两个事件在 `events/ce_poland_events.txt:920`–`:921`、`:943`–`:944` 复用 `.13.d/.13.f`；中文这两键 `:226`–`:227` 用 `SCOPE.sCountry('ce_strong_power')`。只有另一个游说按钮 `:2837` 保存了该 scope。
- 触发：支持国点击筹款或外交声援，KRA 显示通知。
- 后果：援助国名称/口音引用为空或错误，并有缺 scope 的文本求值风险；不能因 `.13` 的另一个调用者正确，就认为 `.14/.15` 已受保护。
- 最小修法：两个调用者在发事件前保存援助国，或为 `.14/.15` 使用不依赖该 scope 的专用本地化；执行和取消边界一起补齐。

### F10 · P2：“波兰或波兰立陶宛已存在”实际要求两国同时存在

- 证据：主 JE `:144`–`:163` 的外层 AND 同时要求 `exists = c:POL`、`exists = c:PLC`，随后才判断其中任一国家独立且至少三整合州。中文 `:13` 明确写“波兰或波兰立陶宛已经存在”。
- 触发：只存在满足资格的 POL 或只存在满足资格的 PLC，KRA 仍存在。
- 后果：这条预定的结束条件不触发；留下与既存波兰政权并行的复国机制。后续 `.10` 无条件 `change_tag = POL` 的冲突行为需另做引擎确认。
- 最小修法：把存在性与其相应国家资格合并为两个互斥安全分支，外层 OR；保留独立和三整合州的设计限制。

### F11 · P2：通牒按钮声明消费战争准备，实际检查和消费另一条进度

- 证据：十个通牒按钮只挂在战争准备 JE `:308`–`:317`；中文按钮描述 `:69`–`:87` 与消费提示 `:96` 均说战争准备。但 KRA 分支检查 `je_ce_polish_reconquest` 的 energy >=100（如按钮 `:184`–`:187`），效果扣该 energy 50（`:272`–`:277`），而非 war_prep。
- 触发：战争准备达到 100、复国影响力未满，按钮仍不可用；反过来影响力达到 100 即按影响力扣费。
- 后果：玩家按当前文案和所在日志投入错误资源。这确认是显示/执行不一致，**不据此替作者决定哪条资源才是设计意图**。
- 最小修法：统一所示条件、消费进度和对应文本；若本意是战争准备，改实际 JE/bar；若本意是影响力，改文字/放置。不能仅把工具提示改成含糊的“进度”。

## 仍需定向验证的风险；不冒充已复现缺陷

### R01 · 高优先：可能把盟友送入另一场外交博弈

`.2` `events/ce_poland_events.txt:144`–`:154` 使用全球 `random_diplomatic_play`，但 limit 跳回 KRA/接收国，只问“是否是任意博弈的发起者/目标”，未在候选博弈上用 `initiator_is`、`target_is`；`.7` `:419`–`:420` 将支持国加入保存的博弈。引擎 docs `effects.log:28791`、`triggers.log:11496`、`:11519` 与 `:11143`、`:14546` 支持“筛选与候选无关”的判断。

但 GAME `events/heavenly_kingdom_events.txt:524`–`:532` 自身也有同形代码，因此此处记录为**高置信度文档/源码风险**，不假装已经观察到错加盟友。最小核验是在世界同时存在两场争端时捕获所保存 DP 的 initiator/target。若按文档语义执行，最小修法是直接在候选 DP 上匹配双方，另核 `.7` 回复时它仍是未开战、允许加入的同一争端。

### R02 · 高优先：通牒与参战邀请未封闭三个月的对象生命周期

`.2/.7` 没有 cancellation_trigger、请求身份或重新检查国家存续、原州所有者、主 JE 仍活动、宣称、外交状态。`.2.a` 直接转保存的州，`.7.b` 直接加入保存的 DP。保存 scope 沿链传递本身是支持的；风险是**对象之后变化**。若州转让或销毁、KRA 改 tag、争端结束，就可能读失效 scope，或让过期回复作用到已不归接收国的对象。需用一个“发请求后州转属/争端先结束”的场景观察实际对象生命周期。

目前通牒需 100、扣 50，确实抑制了同一国家无成本瞬间连点；不能直接声称它无限生成通牒。不过缺少 pending 锁，且外部援助可在事件窗口中补进度，仍允许旧请求未答前发新请求。最小方案是按目标绑定 pending 身份，执行与取消走同一资格判断；不能只随意加一个比事件窗口短的冷却。

### R03 · 中优先：声明胜利可重复排队且按缓存判定

按钮 `:2695`–`:2700` 只读月度缓存的完整控制数 >=5，不检查 `ce_polish_victory_declared`、pending 或当前领土。`.3` `:180`–`:182` 才在回复时写标记。可在结算前重复点击；一个月内丢掉第五州也仍读旧计数。重复事件的真实 UI 去重、排队与失败/完成优先级未验证。最小修法方向是在点击时锁定一次有效结算并刷新实际控制条件，结束后通知不再回写世界状态。

### R04 · 中优先：失败释放 LIT/BYE 未检查既存 tag，立陶宛争端参数需复核

`.11` `:699`–`:745` 在 KRA 完全控制考纳斯时直接 `create_country = LIT`，然后以 `c:LIT` 设置首都、创建战争；`:754`–`:772` 对布列斯特直接创建 BYE。没有既存 LIT/BYE 分支，也没有 `on_created` 保存新对象。若这些 tag 已在别处存活，究竟创建失败、合并还是影响既存国家，不能单凭脚本推断。立陶宛 `create_diplomatic_play` `:727` 只有顶层 target_state，未给 target_country；需对照当前引擎是否能从该州推导国家。不能将允许失国或惩罚性分裂本身记为 bug。

### R05 · 中优先：资格条件与实际目标筛选不完全一致

通牒的 possible 候选（如 `:218`–`:244`）未排除 `has_subject_relation_with = c:KRA`，执行（`:298`–`:320`）会排除。如果剩下的外国州只属于 KRA 的属国，则按钮可能亮、扣50后无事件。主 JE 不允许 KRA 成为属国，但不禁止 KRA 自己拥有属国，故边界并非逻辑上不可达。应把双方候选抽成相同谓词，先证明有目标再扣费。此项需要指定附属关系场景核对原生 trigger 的适用范围。

## 优化假设，必须先确认设计或测量

1. **AI 支持方与反对方行动不对称。** 反对方有 AI 权重，4 个支持按钮（`:2704`–`:2855`）没有 `ai_chance`，而军事工业补贴明确 `value = 0`。支持方无显式 AI 路线是事实，但缺字段的引擎默认和“玩家专用”意图未确认，不能直接说 AI 一定从不援助。也不能说 AI 声索完全无法起步：东加利西亚、考纳斯、布列斯特、沃里尼亚在 claim_count<=3 时有100权重（如 `:2048`–`:2060`）。
2. **GDP 第30名是孤立惩罚尖峰。** 进度条 `:190`–`:203` 的两个独立条件在 rank=30 同时成立，得 -1-3=-4；rank=31 反而 -3。数值事实确定，但它是否违反作者设定尚无明确规格。若是常见连续档位，把第一档 `<30` 或第二档 `>30`，依据选定设计修改。
3. **“军事工业补贴”的基础设施筛选非常窄。** 按钮 `:2991`–`:2993`、事件 `.6 :315`–`:319` 都用 infrastructure_usage=0.3…0.9；文档 `triggers.log:11136` 定义的是使用量，未说比例。若作者想30%–90%，需要真正的比率表达式；若本意就是低使用量州，则不能当成错单位直接改。当前按钮与事件的筛选一致，不是“可用与选择条件不一致”的实例。
4. **宣称按钮可用性应统一为显式候选。** 多个 `NOT = { owns_entire... has_claim... }`（例如 `:106`–`:109`）与执行的“非本国、没有宣称”筛选含义不够透明。此轮不凭其他 Paradox 游戏的 NOT 多子句语义判定可重复刷声索；应原生确认其组合逻辑，再统一为 `any_state` 与 `random_state` 相同条件。实际扣费后是否选到目标应单独记账。
5. **数值变量的 exists 检查需一致。** 多处用 `exists = global_var:数值`，同时又有 `has_global_variable`（bars `:154`、`:260`、`:297`、`:372`；event `:1246`）。引擎文档将 exists 描述为对象非空检查；不能仅凭字段名断言数值0或非0在当前引擎一定会返回什么。依据项目引用规则，未来改动应对数值只用 has_global_variable 分支，避免对象/数值混用。
6. **月度重算可以集中，但无性能数据不要声称已卡顿。** 国家月 pulse 中反复检查全球 KRA/终局状态，年度还逐国做 `any_country` 查询；global JE 已提供一次入口。可把纯全球重算集中，其余仅保留国家本地操作。需要 profile 或日志频率证据才能称性能修复。
7. **终局、进度与资源规则应先写一张状态表。** 例如当前计数只认十个指定地区的完整所有权，不含 Mazovia；开局 KRA 有 Greater/Lesser/Mazovia 和一块 West Galicia，但胜利计数起点为2。这可能是刻意设计，不能因为“看起来是4州”就把数值当错。新计数规则需保留架空地图意图。

## 已排除的误报及清理边界

- **主 JE 月增没有按参与国翻倍。** `context=none`，`.98` 只由 `immediate` 与普通月 pulse 调用；各支持国各有自己的子 JE 进度不是全局条重复累计。开始时多做一次初始化统计也不是无限递增。
- **支持/反对计数不是列表无限追加。** `common/scripted_effects/ce_scripted_effects.txt:206`–`:240` 先清全局列表，再枚举；`:294`–`:317` 清零再计数。可能有延迟一月的缓存，但无证据每月人数翻倍。
- **JE 上添加国家修正是支持的。** `effects.log:312`–`:314` 支持 journal_entry，原版 JE 文档说明向国家传播。子 JE 结束回调在 country scope 清理、周 pulse 却在 JE scope 挂修正，两者不一致需要整理；但不能在没有 JE 销毁传播证据时断言战争/阻击修正永久泄漏。`on_invalid` 少写90级清理（JE `:627`–`:649`）也不单独证明永驻。
- **保存 scope 不会被另一国变量覆盖。** `.2 → .7` 是连续事件链；没有证据同名 `save_scope_as` 等于全局唯一共享指针。需要保护对象生存与请求身份，不要不必要地改成全球变量。
- **POL改国号、LIT/BYE分裂、KRA被吞并都是已有结局。** 用户接受失败/失国，不提议自动救援或强制转国。审计只处理对象、条件、时序与结果一致性。
- **旧通用“州或战争”按钮未被挂载。** `ce_polish_diplo_play_btn` 的 JE 引用在 `:305` 注释，里面缺 `ce_from_country` 不能直接算作当前玩家可达路径；实际十个地区按钮均保存发送国，只有波森保存的领土类型错误。
