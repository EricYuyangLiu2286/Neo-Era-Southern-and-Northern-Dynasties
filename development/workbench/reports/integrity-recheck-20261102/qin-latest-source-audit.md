## Populations and cultural conversion

Original author Huaxia conversion is unchanged since f18b6c4: MOD `common/scripted_effects/ce_scripted_effects.txt:20`–32 iterates real state pops and calls `change_pop_culture` with 1.00; its event caller is `events/ce_culture_events.txt:40`. DOC `effects.log:646`–654 explicitly defines percentage culture/religion conversion in pop scope. GAME `events/brazil/culture_south_america.txt:382`–391 demonstrates partial culture conversion, and `events/japan_events/japan_religion_events.txt:139`–147 religion conversion. These are identity changes, not population-deletion APIs.

The Qin chain at MOD `common/scripted_effects/nesnd_qe1_identity.txt:37`–40 first marks half the Han-Qiang pops, then independently re-enumerates the temporary cohort for full religion conversion and full target-culture conversion. It does not save/reuse the original split pop, halve twice, change size, kill pops or create replacement pops. The selected culture/religion scopes are checked before calling the converter at line 4400. All three passes are in one immediate effect. This supports code validity; it does not prove synchronous split/merge visibility, rounding, employment preservation or total-population conservation in the engine.

One recoverability gap: cleanup of an existing temporary cohort runs separately in monthly/state-owner hooks. Call `nesnd_qe1_clear_orphan_cohort` immediately before the 50% pass so an old cohort cannot be mixed into the new transaction. Preserve its current religion, per the approved recovery contract.

`create_country` DOC `effects.log:878`–889 requires a real state/province and runs `on_created` on the new country. The native KAZ chain (GAME `events/soi_events/00_ep1_kazakh_events.txt:61`–68) uses exactly origin+actual state. It does not create empty demographic templates or erase state pops. Current Qin seeds nevertheless lack a positive-population guard: use state-scope `state_population > 0`, supported by DOC `triggers.log:14458`–14463, in both availability and seed selection, including QRC/QFR. If no positive seed exists, skip that new tag; never fabricate population. Existing recipients may still receive empty territories. A fallback QFR may be created only from a populated remaining state; if none exists, leave residual empty regions with an existing owner rather than creating a populationless country.

## Armies and technologies

DOC `create_country.origin` only promises unspecified inherited values: it does not certify technological inheritance. Minimum explicit newborn prerequisites: `line_infantry` and `artillery`, required by GAME `common/combat_unit_types/00_land_combat_unit_types.txt:101` / `:406`; `add_technology_researched` is documented at DOC `effects.log:448`. Qin already starts with both through history line 7 → GAME `common/scripted_effects/00_starting_inventions.txt:53`–62. This justifies a two-tech floor, not granting whole tech tiers to newborns or changing existing recipients.

`create_military_formation` at DOC `effects.log:959`–983 creates units located in a state_region. Native KAZ creates 5 infantry + 5 cavalry at its new capital (`00_ep1_kazakh_events.txt:88`–103). The interface does not promise to create population, full manpower or free barracks. Each selected Qin infantry/artillery unit has max_manpower 1000. Current fixed 6+2 newborn units are therefore an 8000-person maximum, not proof of actual staffing.

Ordered current-history sums (`qin-newborn-population-baseline.json`) find positive populations in all 36 initial Qin regions. But hypothetical restored PER/Sistan has only 16,012 people, TUV 49,000 and KAL 77,105: fixed8 unit ceilings equal 49.96%, 16.33% and 10.38% of their entire populations. Larger partitions contain 521,200–5,580,550 people. This is a concrete scaling concern. Size any added contingent after full territory transfer using current population and already inherited army/barracks; do not count units as staffed soldiers or size from a random seed alone.

## Reward/tooltip review boundary

Qin recovery gives ±20% army combat and −20% military goods for 15 years. Native Bulgarian JE `05_bulgaria_je.txt:71`–78 grants the same +20% attack/defence plus conscription/morale for 20 years but decays (`static_modifiers/bulgarian_modifiers.txt:26`–31; `script_values/event_values.txt:43`). Qin's flat 15-year duration is substantial, not an obvious weak reward. Its civil alternative bundles bureaucracy+25%, construction+15%, tax capacity+20%, assimilation/conversion+50% for 15 years: individual native magnitudes exist, but the nationwide combined package is broader. For comparison, native Philippine assimilation+50% applies only its selected states for 10 years (`06_philippines_je.txt:387`–393; `00_ip4_03_modifiers.txt:61`–64), and Macao construction+15% is local/10 years (`portuguese_colonialism_events.txt:1112`–1115). Do not inflate rewards merely because numbers look small.

Current unity progress already exposes 11 monthly components and costly population measures; lineage pressure is cached for UI. Native conditions/costs can remain visible, with technical lifecycle/cooldown guards hidden. Court bars show current scores but no formula decomposition. Any simplification should preserve the condition/effect contract and cached computation, not erase guards to shorten a tooltip. Visual tooltip length was not measured in-game.

## Assessment of root's proposed bounded army repair

Deferring preparation until the two-day launch/monthly fallback, after all territorial transfers, is compatible with the spec. Preserving an existing nonzero army avoids extra grants. Zero units below 50,000 population, then 1/2/4/8 at 50,000/100,000/200,000/400,000, capped by both country and capital population, keeps the created max-manpower ceiling at or below 2% of each denominator. It does not promise actual recruitment. Record one-time preparation even when tier zero or an inherited army means no grant, preventing a failed launch/retry from replenishing units. The two-tech floor and preparation must apply only to newly restored recipients; QFR needs that marker as well. QRC retains its separately approved civil-conflict force/goal with tech and population guards only.

Keep the positive-pop check within the absent-tag creation branch; unchanged existing recipient transfers may legitimately receive an empty region. Use the same positive-state predicate in availability and ordered selection. Native selection shape appears at GAME `events/american_civil_war/acw_events.txt:505`–512, supported by DOC `effects.log:16993`. If QFR has no populated seed, skip creating it and leave remaining empty territory with an existing owner. This prevents new populationless tags without manufacturing people.

The plan addresses the identified source problems. Final source review must still inspect the actual edited branches, one-time markers, zero-army outcomes, goal holders/targets and inherited-country preservation; this assessment is not an implementation or engine PASS.
