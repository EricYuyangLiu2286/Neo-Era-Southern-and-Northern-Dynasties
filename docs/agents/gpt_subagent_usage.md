# GPT 子代理使用规则（Codex）

适用于在 Codex 中开子代理。其他代理可参考第 1、3、4 节的原则。

## 1. 什么时候用子代理

子代理从零开始，看不到主代理已读过的设计、作者样本和对话。所以：

- **用**：彼此独立、只读、结果能用“文件:行号 + 一句结论”交回的工作。例如同时在 GAME、MOD、原作 tag 三处找同类实现；统计用词；对已完成的改动做一次独立审查。
- **不用**：内容树的设计、玩家文字定稿、最终合入主 MOD、与作者确认设定。这些需要完整上下文，由主代理做。
- 小任务（一两个文件、原因清楚的修复）不开子代理。

## 2. 等级

| 等级 | 任务 | 模型 / 强度 |
|---|---|---|
| 一级：检索 | 找定义与引用、列原版同类实例、读日志并归组、统计词频、格式与 BOM 检查 | `gpt-6.1-sol` / medium |
| 二级：实现与审查 | 在主代理划定的文件范围内按已定方案写脚本；脚本审查、找 bug；对照原版检查接口 | `gpt-6-astra` / medium |
| 三级：独立复审 | 大批改动交付前的独立复审；玩家文字的冷读（对照 author-samples 指出不像作者的句子，不代写定稿）；复杂设计的另一套方案 | `gpt-6-astra` / high |

- 上限是 `gpt-6-astra` / high。不用 Luna；不用 xhigh 及以上。
- 开子代理时写明模型和强度，不依赖继承的默认值。指定模型不可用时，改用同级或更低的可用模型，并在交付说明里写一句。

## 3. 怎么交代任务

给子代理的指令包含：

1. 要回答的一个问题，或要完成的一件事；
2. 读哪些路径（GAME、主 MOD、tag `original-20261030`）、写哪些文件（只读任务写“不改文件”）；
3. 交回什么：结论、证据位置（文件:行号）、没查到或不确定的部分。

不让子代理再开子代理。同时运行的子代理一般不超过 3 个。

## 4. 主代理怎么用结果

- 子代理的结论是线索：主代理读它给出的关键行，再采用。
- 子代理写的代码，主代理读完差异再合入。
- 交付说明里用一行写明用了哪些子代理、做了什么即可，不需要逐个记录配置。
