# 任务提示词工具包

用途：先开一个“提示词会话”，把作者的原始想法整理成交给开发代理（Codex / Claude）的任务提示词，再到开发会话里使用。

## 1. 提示词会话的开场白（整段复制）

```
你的工作是帮我把维多利亚3 MOD（NESND，北明世界）的开发需求，整理成交给开发代理的任务提示词。你不写代码、不改文件，只产出提示词。

开发代理会读：主 MOD 的 AGENTS.md → 技能 nesnd-victoria3（写文字时另读 nesnd-player-writing）→ docs/agents/STATUS.md。提示词只需写清本次任务；技能里已有的规则不要重复。

技能的分工，供你选用：
- 修 bug、读 error.log、游戏更新 → references/debugging-and-updates.md
- 新内容或改造日志链、事件、按钮、进度条 → references/content-design.md（先选形状、画树）
- 玩家文字 → nesnd-player-writing
- 版本迁移 → references/migration.md；检查与交付 → references/verification.md

我给你需求后，按顺序做：
1. 用三四句话复述：我观察到什么、我期望什么、我怀疑的原因（如有）。
2. 判断任务类型：修复 / 新内容 / 文字 / 迁移 / 工具。
3. 只问开发代理无法从文件推断、又会改变做法的问题，最多 3 个。通常是：设计意图、我怎么观察到的（新开局还是同一存档、几次）、修复后应是什么样子。不问能在代码里查到的事。
4. 我回答后，按 docs/agents/prompt-kit.md 第 2 节对应模板写出提示词，放在一个代码块里。
5. 写完自查：
   - 观察、期望、范围、游戏是否启动、停在哪一步、交付内容，每项都写了；
   - 没有“全面检查”“顺便优化”这类无边界的话；
   - 交付需要我决定的事（设定、数值）写成“先问我”，其余让代理直接做。

写提示词用中文，专名照我的原话，不替我补设定。
```

## 2. 任务模板

### 通用头（每个提示词都有）

```
本次任务：【一句话】
类型：【修复 / 新内容 / 文字 / 迁移 / 工具】
游戏：【本次不启动游戏，由我复测 / 允许启动：……，做完即停】
范围：只做本任务。发现的其他问题列在交付说明里，不顺手改。
```

### 修复

```
我看到的：【现象，在哪个界面、哪个时间点；附截图/存档名】
怎么看到的：【新开局 N 次 / 同一存档重复读取 / 观察者局】
应该是：【设计意图】
怀疑：【我的猜测，可省】

按 debugging-and-updates.md：先保存 logs/；找到决定这件事的脚本，说明为什么会出现我看到的结果；对照原版同类写法和 tag original-20261030。
先用几句话告诉我原因和改法。需要我决定设定或数值时先问；原因清楚时直接修。
交付：改了哪些文件；原现象为什么不会再出现；我复测时看哪里、需要新开局还是读档。
```

### 新内容

```
内容：【哪个国家/势力，玩家面对什么处境，想玩到什么】
时间与终点：【开始年份、大致时长、怎样算结束（成功/失败/超时）】
规模：【参照 content-design.md 的某种形状；大致几个日志、按钮、事件】
必须保留：【已有设定、人物、名词】

先按 content-design.md 画出内容树（日志、状态量、行动、事件、结局），交给我确认，再写脚本和文字。
```

### 文字

```
范围：【哪些文件或键】
问题：【例如“平衡腔”、某些词反复出现、英文直译】
按 nesnd-player-writing：以 tag original-20261030 的同字段原文为样本。先改 10 条代表键给我看，确认后再批量改。动态代码、数字、颜色逐键保持不变。
```

### 游戏更新 / 迁移

```
游戏已更新到：【版本】
按 debugging-and-updates.md 第 2 节：确认版本、刷新索引、列出失效引用，按 migration.md 迁移并保留设计意图。先交失效清单和迁移计划，再动手。
```

## 3. 示例：HNA 在明内战开始时独立

**作者原话**：现在的 USM 内战日志中，湖广总督府/HNA 总是在战争开始时独立，而不是按预定设计约 95% 加入拥护大明联邦一方。按统计，95% 时我不该经常看到独立。想知道原因；若是内战外交博弈的加入设计错误或其他问题，需要修复。

**提示词会话的复述与提问**：

> 观察：多次看到 HNA 在 USM 内战开始时独立。期望：约 95% 加入拥明一方。类型：修复。
> 1. 你是怎么看到的：多个新开局，还是同一存档反复读取？（同一存档读档时，随机结果往往重复，结论会不同。）
> 2. “独立”指什么：脱离宗主后保持中立，加入另一方，还是作为新国家被释放？
> 3. 95% 是你原作中的设计，还是后来改过？修复后是否保留约 5% 独立的可能？

**作者回答后得到的提示词**（括号内按回答填写）：

```
本次任务：查明并修复 HNA（湖广总督府）在 USM 内战开始时独立、而不是约 95% 加入拥明一方的问题。
类型：修复
游戏：本次不启动游戏，由我复测。
范围：只做本任务。发现的其他问题列在交付说明里，不顺手改。

我看到的：USM 内战开始时，HNA 【脱离并保持中立 / 加入另一方】。
怎么看到的：【新开局 N 次，独立 M 次 / 同一存档读档 N 次】。
应该是：约 95% 加入拥护大明联邦的一方，约 5% 独立。【按回答保留或修改】
怀疑：内战外交博弈的加入指令设计有误。

按 debugging-and-updates.md 处理：
1. 先保存 logs/。
2. 找到决定 HNA 在内战开始时走向的全部脚本，可从 events/usm_civilwar_events.txt、common/journal_entries/ce_usm_the_last_days_of_ming.txt、common/diplomatic_plays/、common/on_actions/ 入手。列出从内战开始到 HNA 选边的完整顺序：哪个事件或回调先执行，95% 写在哪里（random_list、ai_chance 还是别的），独立又是在哪里发生的。
3. 说明为什么实际结果常与 95% 不符。至少排查：这次掷骰是否真的执行（触发条件、作用域、执行时 HNA 的宗主关系）；独立是否走了另一条先执行的路径；AI 权重是否被修正值覆盖；原版外交博弈的 AI 选边是否覆盖了脚本加入。
4. 对照原版同类写法，以及 tag original-20261030 里这段原来的写法，看是不是后来改坏的。

先用几句话告诉我原因和改法；改法会改变设定时先问我，原因清楚时直接修。
交付：改了哪些文件；为什么原现象不会再以高频出现；我复测时看哪里，需要新开局还是读档。
```
