## 2. 日志一：「宫廷力量」（nesnd_court_power）

### 2.1 适用条件

```
NOT = { c:RUS ?= this }
OR = { country_tier = empire country_tier = hegemony }
country_has_monarchy_law = yes
can_have_favorites = yes      # 含 IP5 DLC、非共主邦、四种权力分配之一
```

`is_shown_when_inactive` 与 `possible` 用同一组条件，自动出现。结局只有一个可见的“不再适用”（见 §4.5）。

开局适用（源码推断）：奥地利、沐帝国（CNE）、西秦（QE1）、波斯、奥斯曼，以及原版其他独裁帝国。明（USM）、法国、英国开局是财产投票，宠臣不可用，不显示。

### 2.2 两种情形

每周判定一次，存为国家变量 `nesnd_court_case`：

- **A 派系相争**：宠臣不是最大利益集团（`ig_clout` 最高）的领袖。宠臣与最大集团领袖同属一个集团但不是同一人时，也算 A，文字写“同一集团内的门户之争”，影响力对比一项记 0。
- **B 大权臣**：宠臣就是最大集团的领袖。
- **宠臣空缺**：君主还没任命宠臣。界面宠臣窗口显示空位，按情形 A 的文字说明“宫中尚无宠臣”。

### 2.3 三条进度条

都用 `scripted_progress_bar` 的原生 `monthly_progress` 写自然增减，来源以具名条目显示在条的明细里。按钮与事件用 `add_progress` 改条。每周把三条的值抄进国家变量（供修正、换人保留和两个日志交接用），这样每条只有一个写入者。

**① 宠臣权势**（`nesnd_court_power_bar`，0–100，首次初值 20）

修正按 权势/100 线性缩放，0 时无负面：

| 满值修正 | 键 |
|---|---|
| 宠臣所属集团 势力 +30% | `interest_group_ig_<集团>_pol_str_mult = 0.3` |
| 宠臣所属集团 人口吸引力 +30% | `interest_group_ig_<集团>_pop_attraction_mult = 0.3` |
| 政府基础合法性 +30 | `country_legitimacy_base_add = 30` |
| 法律草案进度 +30% | `country_law_enactment_speed_mult = 0.3` |

宠臣所属集团的标记：每周把 `ruler 之外持有 favorite 角色的人物.interest_group` 存为国家变量 `nesnd_court_fav_ig`。原版的集团专属修正是国家修正，所以为原版 8 个集团各写一个静态修正（MOD 没有新增集团），`scaling_modifiers_while_active` 里每个修正的缩放值写成“`var:nesnd_court_fav_ig` 是该集团时取 权势/100，否则 0”。这样整套修正都挂在日志上，日志失效即撤销，不用手动清理。

月度自然增减：

| 来源 | 数值/月 | 理由 |
|---|---|---|
| 宠臣在任 | +0.6 | 基础积累，约 7/年 |
| 宠臣空缺 | −0.3 | 无人经营，缓慢流失 |
| 宠臣所属集团在政府 / 在野 | +0.4 / −0.4 | 在朝才有门路 |
| 宠臣所属集团满意 / 愤怒 | +0.3 / −0.6 | 本集团支持与否 |
| 宠臣有“政治操作”特质（IP5 三级） | +0.2 / +0.4 / +0.6 | 原版宠臣升级用的就是这组特质 |
| 宠臣与君主意识形态相同 | +0.3 | 君臣相得 |
| 正在推行的法律：宠臣赞成 / 反对 | +0.3 / −0.3 | 法律与宠臣利益 |
| 合法性 ≥ 75 / < 25 | +0.2 / −0.5 | 君主威望撑不撑得住宠臣 |
| 国家违约（`in_default`） | −1.0 | 经济崩坏，宠臣担责 |
| 周收支为负 | −0.3 | 财政吃紧 |
| 战争中且厌战 ≥ 50 | −0.5 | 战事不利 |
| 动乱（turmoil）≥ 25% | −0.5 | 地方不稳 |
| 平衡点 ≤ 30 / ≥ 70 | +0.3 / −0.3 | 平衡偏向谁，谁的权势就涨 |
| 宠臣类型（§2.6） | 见该节 | |

平常年景约 +1.3/月（约 15/年），与原版沙皇每完成一项使命 10–15 点的节奏相当。合法性一项与修正中的合法性 +30 构成正反馈；上限只有 +0.2，影响有限，实测时留意。

平常 6–8/月，约 13–16 个月一件；多事时约 7 个月一件。日志每周检查：满 100 时触发一件宫廷事件并清零。平衡点 ≤ 10 或 ≥ 90 时，从极端事件池抽取，否则从常规池抽取。

**③ 权力平衡点**（`nesnd_court_balance_bar`，0–100，初值 50，原生 `marker = yes` 两端标记）

- 情形 A：0 端是宠臣一方，100 端是最大集团一方。
- 情形 B：0 端是大权臣，100 端是其他所有派系。
- 条的名称、两端说明和明细随情形换文字（`first_valid` 选本地化）。

| 来源 | 数值/月（正数＝向 100 端） | 适用 |
|---|---|---|
| 自然回归中点 | 向 50 移 0.25 | 两种 |

| 宠臣集团在政府而最大集团在野 / 反之 | −0.5 / +0.5 | A |
| 两人意识形态相同 | 向 50 再移 0.5 | A |
| 大权臣所在集团影响力 ≥ 40% / ≥ 25% | −1.0 / −0.5 | B |
| 愤怒的在朝集团 ≥ 2 个 | +0.5 | B |
| 宠臣权势 ≥ 85 / ≥ 60 | −1.0 / −0.5 | 两种 |
| 合法性 < 25 | +0.5 | 两种 |
| 动乱 ≥ 25% | +0.5 | B |

平衡点的修正（随偏离中点的程度线性缩放，满偏离时取下表）：

| 偏向 | 情形 A | 情形 B |
|---|---|---|
| 偏 0 端 | 宠臣集团赞同 +2，最大集团赞同 −3 | 大权臣集团赞同 +2，其余集团赞同 −1 |

实现同权势：每个集团的 `…_approval_add` 静态修正 × 缩放值，挂在日志上。

### 2.4 按钮（6 个，情形不同时换名称和文字）

费用沿用原版两档：常规 5（有选举权 10），重大 10（有选举权 20）。`cost` 字段只作显示，扣费写在效果里。

| # | 名称（A / B） | 费用 | 冷却 | 条件 | 效果 |
|---|---|---|---|---|---|
| 1 | 借宠臣之手推法 | 重大 | 2.5 年 | 正在推行法律，且宠臣对该法赞成 | `add_enactment_phase = 1`；平衡点 −8 |
| 2 | 恩赏宠臣一派 / 恩赏权臣门下 | 常规 | 5 年 | 有宠臣 | 宠臣集团 5 年修正：赞同 +3、势力 +15%；平衡点 −10 |
| 3 | 安抚[最大集团] / 抚慰诸派 | 常规 | 5 年 | 有宠臣 | A：最大集团 5 年赞同 +3；B：其余在朝集团 5 年赞同 +2；平衡点向 50 移 15 |
| 4 | 放手宠臣 / 委政权臣 | 0 | 2.5 年 | 有宠臣 | 权势 +15；平衡点 −15；A：最大集团赞同 −1（2.5 年）；B：其余集团赞同 −1 |
| 5 | 整肃宫禁 | 常规 | 2.5 年 | 宫廷事件 ≥ 30 | 宫廷事件 −40 |
| 6a | 打压[最大集团领袖]（A） | 重大 | 5 年 | 平衡点 ≥ 80，对方可被移除（§4.3） | 弹极端事件 X4′（见 §2.7） |
| 6b | 剪除权臣（B） | 重大 | 5 年 | 平衡点 ≤ 20，宠臣可被移除 | 弹极端事件 X2′ |

取舍关系：按钮 4 是唯一增加权势的按钮，代价是平衡点倒向宠臣；按钮 3 花权势把平衡点拉回中点；按钮 1、2 花权势换实利，同时让平衡点继续偏。

AI（`ai_chance`，保留 20 点不花）：

| 按钮 | AI 权重 |
|---|---|
| 1 | 有可花余量且该法是 AI 想要的（复用 `je_tsarpoints_ai_wants_law` 同类判断）：60；否则 0 |
| 2 | 宠臣集团赞同 < 0：25；否则 5 |
| 3 | 平衡点 ≤ 30 或 ≥ 70：40；否则 5 |
| 4 | 权势 < 40 且平衡点 ≥ 35：20；否则 0（不在已偏向宠臣时继续加码） |
| 5 | 宫廷事件 ≥ 70 且权势 ≥ 40：15 |
| 6a/6b | 5（只在极端区间可用） |

这样 AI 权势低时会补，高时会花，平衡点偏时优先拉回。

### 2.5 界面

自定义 GUI `gui/journal_entry_widgets/nesnd_court_power.gui`，照原版人物面板写法：

- 左窗：最大利益集团的领袖（`Var('nesnd_court_top_leader').GetCharacter`），下方显示集团名。
- 右窗：宠臣（`Var('nesnd_court_favorite').GetCharacter`）。空缺时显示空框和“宫中尚无宠臣”。
- 同一人时两个窗口照常显示同一人，中间加一行“大权臣”字样。
- 三条进度条用原生显示，不进自定义 GUI。
- 按钮用默认按钮列表（见 §6 第 3 问）。

### 2.6 宠臣类型（建议做，3 种）

判定用原生 `law_stance = { law = law_type:law_monarchy value … }`，对原版和本 MOD 的人物意识形态都适用（没有写政体态度的意识形态算中立）。代价：一个共用 scripted trigger，按钮和进度条里各加几个分支，事件里换几处文字。不需要新系统。

| 类型 | 判定 | 进度条 | 按钮 | 事件 |
|---|---|---|---|---|
| 近臣（拥君） | 赞成或强烈赞成君主制 | 权势 +0.2/月；平衡点回归中点加快 0.25 | 按钮 4 平衡点位移减半（−8） | 不抽“逼宫”；更易抽“行刺宠臣”（被他派视为君主爪牙） |
| 幸臣（中立） | 中立 | 无 | 默认 | 默认 |
| 权臣（疑君） | 反对或强烈反对君主制 | 权势 +0.4/月；宫廷事件 +2/月；平衡点 −0.5/月 | 按钮 4 权势 +20；按钮 3 多花 5 点 | “逼宫”权重 ×2 |

## 4. 两个日志的共同部分

### 4.1 换人保留（建议值，待确认）

每周比较存下的人物与现任人物，发现变化即结算：

| 情形 | 权势 | 平衡点 | 宫廷事件 |
|---|---|---|---|
| 宠臣更替（死亡、撤换、新君即位后重新任命） | ×0.5 | 偏离中点的部分 ×0.5 | 不变 |
| 共和换届，新统治者与前任同属一个集团 | ×0.7 | 偏离 ×0.5 | 不变 |
| 共和换届，不同集团 | ×0.5 | 偏离 ×0.5 | 不变 |
| 最大集团易主，或其领袖更替 | 不变 | 偏离 ×0.5 | 不变 |
| 情形 A ↔ B 切换 | 不变 | 偏离 ×0.5（两端含义变了） | 不变 |
| 君主制 ↔ 共和国（换日志） | ×0.3 | 回到 50 | 清零 |

新君即位时引擎先撤销宠臣（`00_code_on_actions.txt:1584`）。空缺期权势按 −0.3/月流失，直到任命新宠臣时再按 ×0.5 结算。如果觉得双重损失太重，可改为空缺期不流失（§6 第 5 问）。

### 4.2 两个日志的交接

三条的值每周抄到同一组国家变量（`nesnd_court_power_var`、`nesnd_court_balance_var`、`nesnd_court_intrigue_var`）和一个政体标记 `nesnd_court_regime`（1 君主 / 2 共和）。新日志 `immediate` 读变量，按上表结算后写入自己的条。两个日志的适用条件以君主制法与共和法区分，互斥，不会同时存在。失去等级后再恢复、政体不变时，原值照旧。

### 4.3 共用的移除判定

一个 scripted trigger `nesnd_court_character_removable`（人物作用域），两个日志所有会杀死、流放或撤销人物的事件、按钮都用它：

```
is_character_alive = yes
is_immortal = no                                   # 永生人物；郭庆达、寿汴辩的连任保护与洪秀全都靠这一项
NOT = { nesnd_story_character_protected = yes }    # MOD 已有的剧情保护（洪秀全旅程、南朝起事人物、明宗室、拿破仑三世、加里波第等）
owner ?= { NOT = { has_variable = favorite_event_active_var } }  # 原版宠臣事件进行中不动（国家变量）
```

事件 `trigger` 检查目标可移除；选中后若目标在等待期间失去资格（如刚设了永生），`immediate` 里只给修正、不移除。

### 4.4 节奏与 AI 总表

- 宫廷事件约每 13–16 个月一件；极端事件只在平衡点进入 10/90 以外时出现。
- AI 保留 20 点；按钮 4 只在权势低且平衡点未倒向宠臣时用；按钮 3 在平衡点偏离 20 以上时优先。
- 事件 AI 选项：平衡点偏向哪边，就偏好把它拉回中点的选项。

### 4.5 结束

- 可见结局：“不再适用”，条件为 §2.1 / §3.1 的否定（按等级、政体、宠臣可用分别列项，玩家能看出是哪一项失效）。效果：撤销按钮加的定时修正（照原版 `je_tsarpoints_cleanup_master_modifiers`），保留三组变量供交接。缩放修正随日志自动撤销。
- 不做失败事件弹窗（原版有，作者未要求）。若需要，可加一个提示性事件。
